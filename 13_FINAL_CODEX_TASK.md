# 13 — ФИНАЛЬНАЯ ЗАДАЧА ДЛЯ CODEX

## Роль
Ты создаёшь первую рабочую версию мобильного веб-калькулятора покупок JIMON.

Это небольшой, понятный mobile-first инструмент, а не интернет-магазин и не CRM.

## Технологии
Создать:
- React 18+
- TypeScript
- Vite
- обычный CSS/CSS Modules или простой понятный способ стилизации
- без backend для первой версии
- mobile-first
- данные хранятся локально в приложении
- состояние плана можно хранить в localStorage

Не добавлять ненужные библиотеки.

## Экраны

### 1. Главный экран
Два пути:
- `Я новичок`
- `Я партнёр`

### 2A. Новичок
Короткий экран `Как это работает`.
Стартовые параметры:
- 0%;
- товарооборот 0 ¥.

### 2B. Партнёр
Модальное окно:
- скидка 10/20/30/40/50/60;
- накопленный товарооборот;
- `Не помню товарооборот`.

### 3. Каталог
Обязательно ДВА ряда фильтров.

Тип:
`Все | Единичные | Комплекты`

Направление:
`Все | Красота | Здоровье`

Также:
- поиск по названию;
- карточки товаров;
- фото;
- русское название;
- китайское название;
- актуальная цена;
- `Добавить в план`;
- постоянная кнопка `План покупок · N`.

Не заменять `Здоровье` на `Для тела`.
Не убирать кнопку `Все` ни в одном из двух рядов.

### 4. Добавление товара
Показать количество и расчёт конкретного заказа.
Реализовать правила из `12_PURCHASE_PLAN_SPEC.md`.

### 5. План покупок
Каждый товар = отдельный заказ.
Показать:
- цена каталога;
- количество;
- применяемая скидка;
- цена со скидкой;
- услуги курьера;
- к оплате.

Порядок заказов можно менять стрелками.
После каждой перестановки пересчитать весь план.

### 6. Итог
Показать:
- итог к оплате;
- экономию;
- уровень скидки для следующих покупок.

## Данные

Использовать `02_JIMON_MASTER_DATA.xlsx` как источник фактических магазинных цен.

Важно:
- магазинную цену уровня НЕ вычислять процентом;
- брать фактическое значение из таблицы;
- если цена для выбранного уровня отсутствует — показывать `Цена уточняется` и запрещать добавление позиции по этому уровню;
- никаких выдуманных цен 50/60%.

### Не включать
Из листа `Товары` пока не включать:
- старую позицию Цзиньму в саше;
- старую позицию Баоцин в саше;
- BB-кушон;
- JIMON / Jinmu AI Xiaozhi.

Лист `Акции` полностью игнорировать.

## Товарооборот

Товарооборот:
`цена каталога × количество`.

Не использовать для товарооборота:
- цену со скидкой;
- услуги курьера.

## Услуги курьера

Единичный товар:
- 1–5 шт. одного наименования = 12 ¥ за весь заказ.
- более 5 шт. автоматически не рассчитывать по правилу 12 ¥.

Комплект:
- 12 ¥ за каждый комплект.

## Изображения

Не генерировать новые упаковки.
Не использовать картинки, придуманные ИИ.

Для первого этапа:
- предусмотреть папку `src/assets/products/`;
- использовать только реальные изображения, которые владелец положит туда;
- если конкретного файла пока нет, использовать нейтральный placeholder `Фото будет добавлено`, а не выдумывать упаковку;
- одна позиция должна ссылаться на один стабильный файл изображения на всех экранах.

Создай понятную модель `Product`, включающую минимум:

## Расчётный движок

Логику расчёта вынеси в чистые TypeScript-функции, отдельно от UI.

Нужны функции минимум:
- получить уровень скидки по товарообороту;
- получить фактическую цену товара для уровня;
- рассчитать услуги курьера;
- рассчитать один заказ;
- последовательно пересчитать весь план;
- рассчитать итоговую экономию;
- рассчитать уровень после плана.

Добавь простые unit-тесты на расчётную логику, если тестовый раннер можно подключить без перегруза проекта.

## Обязательные тестовые сценарии

### Сценарий A — новичок
Старт 0%, оборот 0.
Первый заказ достигает первого порога.
Новая скидка применяется только ко второму заказу.

### Сценарий B — партнёр
Стартовая скидка 30%, известный оборот.
После достижения 22 000 ¥ скидка 40% применяется только к следующему заказу.

### Сценарий C — количество
Единичный товар × 5:
курьер 12 ¥ за заказ.

### Сценарий D — комплект
Комплект × 3:
курьер 36 ¥.

### Сценарий E — перестановка
Поменять местами два заказа и проверить, что применяемые скидки и итог пересчитались.

## Важное ограничение
