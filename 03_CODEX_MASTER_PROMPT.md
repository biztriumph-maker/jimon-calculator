# MASTER PROMPT ДЛЯ CODEX — JIMON CALCULATOR

Ты работаешь над отдельным мобильным веб-приложением JIMON — калькулятором покупок/заказов для новичков и партнёров.

## 1. Цель продукта
Приложение должно:
- помогать новичку сформировать последовательный план покупок и видеть, как уже внутри текущего плана меняется доступный уровень скидки;
- помогать партнёру указать действующую скидку и стартовый накопленный товарооборот, чтобы корректно рассчитывать возможный переход на следующий уровень;
- позволять выбирать единичные товары и комплекты;
- фильтровать товары по направлениям;
- искать по названию;
- показывать фактические цены JIMON;
- считать отдельные заказы, итоговую сумму и экономию.

Приложение открывается по одной ссылке в мобильном браузере. В первой версии нет регистрации пользователя.

## 2. Утверждённые первые три экрана
Используй `01_APPROVED_UI_3_SCREENS.png` как визуальный источник истины для первых трёх экранов.

### Экран 1 — Главный
- логотип JIMON;
- `Здоровье. Качество. Возможности.`;
- `Ваш личный калькулятор покупок`;
- `Просто. Понятно. Выгодно.`;
- карточка `Я новичок`;
- подпись: `Хочу понять, как правильно сделать первые покупки и получить скидку`;
- карточка `Я партнёр`;
- подпись: `Я уже знаю свою скидку и хочу рассчитать стоимость товаров`;
- нижние преимущества:
  - `Актуальные цены`
  - `Учитываем правила компании`
  - `Удобно на телефоне`

На главном экране не показывать уровни скидки.

### Экран 2A — Новичок
Ключевая смысловая формулировка:
`Выбирайте товары, добавляйте их в план покупок и смотрите, как в процессе оформления меняется ваш уровень скидки и какая цена будет действовать для каждого последующего заказа в текущем плане.`

Важно:
- новичок начинает с 0%;
- стартовый накопленный товарооборот новичка = 0 ¥;
- нельзя создавать впечатление, что скидка начнёт работать только при следующем визите;
- скидка может изменяться уже между отдельными заказами внутри текущего плана.

### Экран 2B — Партнёр
Партнёр — это пользователь, у которого уже есть действующая скидка.

Допустимые действующие уровни:
`10% / 20% / 30% / 40% / 50% / 60%`

0% для партнёра не показывать.

Партнёр должен указать:
1. текущий уровень скидки;
2. текущий накопленный товарооборот в ¥.

Если товарооборот неизвестен, должна быть опция:
`Не помню товарооборот`

При включении:
- поле товарооборота становится неактивным;
- расчёт цен идёт по выбранной текущей скидке;
- автоматический переход на следующий уровень скидки не рассчитывается;
- показать пояснение:
  `Расчёт будет выполняться по выбранному вами уровню скидки. Переход на следующий уровень скидки автоматически рассчитываться не будет.`

## 3. Модальное окно партнёра
Перед полноценной работой с каталогом партнёр вводит стартовые данные в модальном окне.

Содержимое:
- заголовок `Ваш текущий уровень`;
- блок `Ваша текущая скидка`;
- кнопки 10/20/30/40/50/60;
- поле `Текущий накопленный товарооборот, ¥`;
- чекбокс/опция `Не помню товарооборот`;
- вычисляемая подсказка о скидке для следующего заказа, только если товарооборот известен;
- основная кнопка `Применить`;
- вторичная кнопка `Отмена`.

Не использовать формулировку `Возможный уровень скидки` для текущей скидки пользователя. Это реальный действующий уровень.

После закрытия модального окна показывать компактную строку состояния:
`Товарооборот: 18 500 ¥ · Скидка: 30% · Изменить`

Если оборот неизвестен:
`Товарооборот: не указан · Скидка: 30% · Изменить`

## 4. Каталог

### Поиск
`Поиск по названию товара`

### Фильтр типа
`Все | Единичные | Комплекты`

### Фильтр направления
`Все | Красота | Здоровье`

`Для тела` нигде не использовать.

Фильтры независимые и могут комбинироваться.
Примеры:
- Единичные + Красота
- Комплекты + Здоровье
- Все + Красота
- Все + Все

Переключение фильтров не должно удалять уже выбранные позиции из плана.

### Визуальное поведение фильтров
- все кнопки одного ряда одинаковой ширины и высоты;
- активная кнопка — насыщенно зелёная;
- неактивные — светло-зелёные/приглушённые, но явно выглядят как доступные для нажатия;
- не должно быть разнобоя по размерам `Единичные`, `Комплекты`, `Красота`, `Здоровье`.

### Компактность
Стартовые данные партнёра после ввода сворачиваются в одну компактную строку, чтобы максимально увеличить видимую область каталога.

Нужна постоянная нижняя кнопка:
`План покупок · N`

## 5. Карточка товара
Показывать:
- фото;
- русское рабочее название — главное;
- китайское название — меньшим размером;
- одну актуальную цену для текущего применимого уровня;
- кнопку `Добавить в план`.

Не выводить все уровни цен одновременно.

Услуги курьера на общей карточке каталога не показывать. Они появляются при формировании конкретного заказа/в плане.

## 6. Направления товаров
Использовать только:
- `Красота`
- `Здоровье`

Комплект наследует направление соответствующего базового товара/линейки.

Рабочее распределение хранится в `07_CATEGORY_MAPPING.md`.

## 7. Логика скидки и товарооборота
Пороговые значения:
- 331 ¥ → 10%
- 1 503 ¥ → 20%
- 5 800 ¥ → 30%
- 22 000 ¥ → 40%
- 220 000 ¥ → 50%
- 660 000 ¥ → 60%

Правила:
1. Текущий заказ считается по скидке, доступной ДО него.
2. Товарооборот текущего заказа добавляется к накопленному после формирования этого заказа.
3. Если достигнут следующий порог, новый уровень начинает действовать только со следующего отдельного заказа в текущем плане.
4. Если партнёр не указал товарооборот, уровень не повышать автоматически.

После каждого заказа допустима формулировка:
`Для следующего заказа доступен уровень скидки — 10%.`

В финале:
`Ваш уровень для следующих покупок: X%`

## 8. Главные правила заказов
1. Одна товарная позиция = один отдельный заказ.
2. Разные товары нельзя объединять в один заказ.
3. Несколько единиц одного и того же товара могут формировать один заказ, если это соответствует структуре магазина.
4. Новая скидка не применяется к заказу, которым она была достигнута.
5. Она применяется со следующего отдельного заказа.

## 9. Услуги курьера
В пользовательском интерфейсе использовать:
`Услуги курьера`

Не использовать:
`Доставка до склада`

Стоимость:
- берётся из данных конкретного товара/заказа;
- не жёстко равна 12 ¥;
- может быть, например, 12 ¥, 24 ¥ или иной;
- входит в `К оплате`.

Пример:
- Цена товара: 319 ¥
- Услуги курьера: 12 ¥
- К оплате: 331 ¥

## 10. Итог плана
Показывать:
- каждый заказ одной строкой/карточкой;
- итоговую сумму каждого заказа;
- `Итого к оплате`;
- `Экономия благодаря скидке`;
- `Ваш уровень для следующих покупок: X%`.

Не выводить отдельной итоговой строкой общую сумму услуг курьера, если она уже включена в итог каждого заказа.

## 11. Цены и данные
Использовать `02_JIMON_MASTER_DATA.xlsx`.

Критически важно:
- не рассчитывать магазинную цену простым вычитанием математического процента;
- использовать подтверждённые фактические цены;
- 50%/60% поддерживать архитектурно;
- если реальной цены 50%/60% нет — не придумывать её.

## 12. Темы
Будущая версия должна поддерживать светлую и тёмную тему с одной и той же структурой.

Переключатель:
- компактный современный switch;
- солнце/луна;
- без текстовых подписей;
- активное состояние должно быть однозначно понятно;
- солнце не использовать как зелёный символ только потому, что тема светлая.

Тема не должна менять продуктовую логику.

## 13. Техническая стратегия
Первая версия:
- React + TypeScript + Vite;
- mobile-first;
- без обязательного backend;
- каталог можно преобразовать из Excel в JSON/TS;
- расчёт на клиенте;
- состояние плана можно хранить локально;
- архитектура должна позволять позже подключить удалённый источник данных/админку.

## 14. Режим работы
Работать блоками:
1. анализ;
2. согласование;
3. точечная реализация;
4. локальная проверка;
5. commit;
6. push только по отдельной команде владельца.

Не менять утверждённую логику самовольно.


# ФИНАЛЬНЫЕ УТОЧНЕНИЯ — ИМЕЮТ ПРИОРИТЕТ НАД БОЛЕЕ РАННИМИ ФОРМУЛИРОВКАМИ

1. Товарооборот = только `розничная цена каталога × количество`.
   Цена со скидкой и услуги курьера в товарооборот НЕ входят.

2. Услуги курьера:
   - единичный товар: 12 ¥ за весь заказ при количестве 1–5 шт. одного наименования;
   - комплект: 12 ¥ за каждый комплект;
   - более 5 единиц одиночного товара автоматически по 12 ¥ не считать.

3. Акции полностью исключить из первой версии. Лист `Акции` игнорировать.

4. Каталог всегда содержит:
   - Тип: `Все / Единичные / Комплекты`
   - Направление: `Все / Красота / Здоровье`

5. В плане заказа показывать:
   - цена каталога;
   - количество;
   - применённая скидка;
   - цена со скидкой;
   - услуги курьера;
   - к оплате.

6. Перестановка:
   - первая карточка — только вниз;
   - средняя — вверх/вниз;
   - последняя — только вверх;
   - после перестановки пересчитать весь план.

7. Фото:
   - только реальные изображения из актуальных скриншотов магазина;
   - не генерировать упаковки ИИ;
   - один и тот же товар использует одно и то же фото на всех экранах.

Подробности: `12_PURCHASE_PLAN_SPEC.md` и `13_FINAL_CODEX_TASK.md`.
